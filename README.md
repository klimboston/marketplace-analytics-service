# Marketplace Analytics Service

Микросервис аналитики маркетплейсов. Предназначен для фонового сбора данных о товарах, сохранения результатов в реляционную базу данных и кэширования частых поисковых запросов.

## Стек технологий

* **Фреймворк:** FastAPI (Python 3.14)
* **Управление зависимостями:** uv
* **База данных:** PostgreSQL (SQLModel / SQLAlchemy)
* **Асинхронный драйвер БД:** asyncpg
* **Очередь задач:** Celery
* **Брокер сообщений и Кэш:** Redis (aioredis)
* **Контейнеризация:** Docker / Docker Compose

## Архитектура проекта

Сервис спроектирован по распределенной схеме:
1. **FastAPI Web Server:** Принимает HTTP-запросы. При чтении проверяет кэш в Redis. При запуске «тяжелых» процессов (парсер) — мгновенно делегирует задачу в Celery и возвращает клиенту ответ.
2. **Celery Worker:** Изолированный фоновый процесс. Извлекает задачи из Redis, запускает асинхронный контекст парсинга и выполняет пакетную запись (Bulk Insert) данных в PostgreSQL.
3. **Redis:** Выполняет двойную роль — брокер сообщений (очередь для Celery) и In-Memory хранилище для кэширования ответов API со временем жизни (TTL = 60с).

## Как запустить локально

### Преструктура
В корне проекта должен находиться файл `.env` со следующими переменными:

```env
PROJECT_NAME="Marketplace Analytics"
DEBUG=True

DB_HOST=db
DB_PORT=5432
DB_NAME=marketplace_db
DB_USER=postgres
DB_PASSWORD=postgres

REDIS_HOST=redis
REDIS_PORT=6379
REDIS_PASSWORD=redis1234
```

### Запуск через Docker Compose

Для сборки и запуска всего окружения (FastAPI, Celery, Postgres, Redis) в изолированной сети выполните:

```bash
docker compose up --build -d
```

После успешного старта контейнеров:
* Интерактивная документация Swagger API будет доступна по адресу: [http://127.0.0](http://127.0.0)
* База данных автоматически инициализирует нужные таблицы (`marketplace`, `product`) при первом запуске через lifespan-менеджер.

### Полезные команды

* Просмотр статуса контейнеров: `docker compose ps`
* Просмотр логов всех сервисов: `docker compose logs -f`
* Остановка проекта с сохранением данных: `docker compose down`
* Полный сброс базы данных и кэша (очистка volumes): `docker compose down -v`
